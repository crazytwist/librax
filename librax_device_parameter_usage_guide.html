01

整体理解

设备模块的参数不是单点配置，而是一条链路：流程启动参数和样本实验参数进入 Flow 上下文，步骤定义与流程节点补齐运行参数，设备指令模板把运行参数渲染成真实报文，设备回调再把结果解析成上下文输出，供后续节点继续引用。
启动参数
defaultInputParams、接口 inputParams、样本 experiment_params
步骤参数
defaultParams、paramsOverride、inputMapping
运行入参
合并为 StepDispatchContext.inputParams，DIRECT/QUEUED 共用
设备报文
requestTemplate 使用 ${xxx} 渲染，并注入系统回调字段
结果回流
data 或 rawResponse 经 Codec 解析，再由 outputMapping 写入上下文
本文以当前代码为准。核心阅读点包括 StepSubmitter、PipelineGraphBuilder、InstrumentStepExecutor、QueuedDispatchSpi、DeviceGatewayImpl、DeviceCallbackHandler 与 CodecExecutor。
02

参数模型

建议把设备相关参数拆成四类，不要全部堆进设备指令模板。这样流程能复用，设备适配也更稳定。

业务实验参数

来自样本、流程启动或节点配置，例如 sampleId、targetPh、volumeUl、temperature。这些参数通常需要透传给设备或计算节点。

设备执行参数

设备命令真正需要的字段，例如 durationSec、speedRpm、channel、methodCode。应在 paramsSchema 中声明，在 requestTemplate 中引用。

系统控制参数

由 Flow 自动生成，例如 executionId、nodeId、callbackToken、callbackUrl。这些参数用于回调路由、鉴权和流程推进。

设备连接与解析参数

保存在 DeviceInfo、DeviceCommand、DeviceCodec 中，例如 baseUrl、httpPath、codecId、pollDoneExpr。它们服务于驱动，不应作为实验业务参数传来传去。

03

参数来源与优先级

当前代码里参数合并分两段完成：启动流程时先构建 input 上下文；每个步骤提交时再合并步骤参数、映射参数和系统参数。

流程启动阶段

来源代码位置作用覆盖关系
PipelineDefinition.defaultInputParamsPipelineExecutionServiceImpl.start流程级默认入参，例如通用阈值、默认设备方法。作为 base。
start.inputParamsPipelineExecutionServiceImpl.start调用方启动流程时传入，例如 sampleId、本次实验目标值。覆盖流程默认入参。
SampleBindHookSampleBindHook.beforeSchedule从样本 experiment_params 注入到 inputParams。使用 putIfAbsent，不覆盖调用方已传字段。

步骤提交阶段

来源代码位置示例优先级
sample.experiment_paramsSampleContextSpiImpl{"targetPh":7.2}低。作为基础层。
launchParamsExecutionContextManager.getNodeOutput(input){"sampleId":"S001"}低到中。可被步骤参数覆盖。
StepDefinition.defaultParamsPipelineGraphBuilder.mergeParams{"durationSec":60}中。步骤默认值。
PipelineStep.paramsOverridePipelineGraphBuilder.mergeParams{"durationSec":90}高于默认参数。
PipelineStep.inputMappingStepSubmitter.resolveInputParams{"ph":"${s_ph.ph}"}高于步骤静态参数。
sys variablesStepSubmitter.resolveInputParamsexecutionId、nodeId、callbackToken、callbackUrl最高，始终覆盖。
最终进入设备模块的是 StepDispatchContext.inputParams。DIRECT 路径由 InstrumentStepExecutor 直接传给 DeviceGateway；QUEUED 路径会先写入 lab_task.payload.inputParams，再由 InstrumentTaskExecutor 取出传给 DeviceCommandSpi。
04

参数定义模块怎么配

参数定义主要落在 Flow 的 StepDefinition 和 PipelineStep，设备模块的 DeviceCommand 只负责把已经合并好的运行参数变成设备报文。

StepDefinition：定义可复用步骤

字段建议定义内容解释
stepKey稳定的小写下划线编码，如 ph_measure。被流程节点引用，是步骤组件的业务身份。
stepType设备步骤使用 INSTRUMENT。决定执行器路由到 InstrumentStepExecutor。
deviceType设备类型，如 PH_METER。用于资源申请和设备网关选择设备。
command默认指令，如 MEASURE。当前运行时实际使用的是步骤定义里的 command。
defaultParams设备参数默认值，如 {"durationSec":60,"unit":"PH"}。适合定义多数流程都一样的参数。
paramsSchema表单 schema，声明参数类型、单位、是否必填、枚举。当前代码主要给前端渲染和后端入参校验预留；运行时不会自动按 schema 校验。
outputFields输出字段声明，如 ["ph","temperature"]。用于后续节点引用提示和文档化，不直接影响回调解析。
mockOutput单独测试或 MOCK 模式输出。用于跳过真实设备时模拟结果。

PipelineStep：定义本流程节点差异

字段建议定义内容解释
paramsOverride只填与步骤默认不同的字段。覆盖 defaultParams 同名字段。
inputMapping从流程上下文或启动参数取值，如 {"sampleId":"${input.sampleId}"}。适合把上游节点输出映射成设备命令参数。
outputMapping从设备回调 outputs 中抽取语义字段，如 {"ph":"$.ph"}。步骤成功后写入上下文，后续节点通过 ${nodeId.field} 引用。
resourceEnabled需要独占设备时设为 true。Flow 会先向 ResourcePool 申请资源，再执行设备步骤。
zoneCode指定区域，如 ZONE_A。影响资源申请和物料校验范围。
command当前不建议依赖。代码注释说可覆盖，但 PipelineGraphBuilder 目前组装时使用的是 StepDefinition.command。

表达式支持范围

表达式含义示例
${input.xxx}读取流程启动参数。${input.sampleId}
${sys.xxx}读取系统变量。${sys.callbackUrl}
${nodeId.field}读取前置节点输出。${s_ph.ph}
${xxx}设备指令模板中的顶层参数替换。${durationSec}
ExecutionContextManager 只在整个字符串形如 ${a.b} 时解析上下文表达式；设备命令模板的 ExpressionUtil.render 则负责渲染 ${xxx} 占位符。建议不要把复杂表达式和拼接逻辑塞进字段值，复杂计算应放到 COMPUTE 节点。
05

设备指令参数

DeviceCommand 是设备适配的核心，它定义“某类设备的某个指令应该怎么发”。

字段标签定义方式与参数关系
deviceType必填设备类型，必须与 DeviceInfo.deviceType、StepDefinition.deviceType 对齐。
commandCode必填指令编码，如 MEASURE、CALIBRATE、START。
requestTemplate必填透传入口请求报文模板，支持 ${param} 替换。这里应该只引用最终 inputParams 中存在的参数。
httpMethodHTTPHTTP 方法。为空默认 POST；当前驱动支持 GET、PUT、DELETE，其他回退为 POST。
httpPathHTTP请求路径，拼接到设备 baseUrl。当前只用 executionId、callbackToken 渲染路径变量。
contentType协议HTTP 下是媒体类型，默认 application/json; charset=utf-8。TCP/SERIAL 注释里作为报文编码格式。
timeoutMs配置指令超时配置字段已存在，但 HTTP 驱动当前主要使用设备连接/读取超时，直接执行接口的 timeoutMs 也只用于 Redis 执行状态超时判定。
retryable配置是否可重试字段已存在，当前重试主要由 Flow/Task 层的 attempts 与 watchdog 控制。
codecId输出解析绑定响应解析规则。设备回调带 rawResponse + deviceType + commandCode 时，会用它解析输出。
completionMode完成模式WEBHOOK 或空表示等待回调，SYNC 表示 HTTP 响应即完成，POLL 表示轮询。DO 和 SQL 已有字段，但当前 Save/Resp VO 未完整暴露该字段。
pollPath / pollDoneExpr / pollMaxTimesPOLL轮询模式使用。pollPath 支持 ${taskId}，完成表达式支持 JSONPath 和简单比较表达式。
mockOutput测试Mock 协议返回数据字段存在，但当前 MockDeviceDriver 只返回随机 taskId，未使用该字段生成回调结果。

requestTemplate 的设计原则

应该放进去
  • 设备必须知道的动作参数：durationSec、speedRpm、volumeUl。
  • 设备需要绑定实验上下文时的业务 ID：sampleId、batchNo。
  • 设备端需要直接回调时的 callbackUrl，也可以依赖 JSON 自动注入。
不建议放进去
  • 设备连接信息：host、port、baseUrl。
  • 设备选择信息：具体 deviceId，除非走直接执行指定设备。
  • 流程内部调度策略：maxAttempts、resourceWaitTimeoutMs。
DeviceGatewayImpl.injectSysFields 会在请求体是合法 JSON 时自动写入 executionId、nodeId、callbackToken 和 callbackUrl。如果请求体是纯文本、HEX、二进制字符串，则不会自动注入，需要模板自己显式包含。
06

哪些参数需要透传

“透传”不是把所有参数都塞给设备，而是把设备执行必须知道、并且设备侧不应该重新推导的字段传过去。

参数类别建议字段是否透传到设备说明
流程身份executionId、nodeId建议透传JSON 请求体会自动注入。设备回调时路径或 body 需要能带回这两个值。
回调鉴权callbackToken必须透传HTTP 请求头 X-Callback-Token 会携带，JSON body 也会自动注入。回调必须带回。
回调地址callbackUrl视设备能力透传如果设备支持动态回调地址，建议传。流程中 INSTRUMENT 节点自动生成 /device/callback/{executionId}/{nodeId}。
样本身份sampleId、sampleIds通常透传设备或中间件需要知道当前测量对象时传；如果设备只做动作不关心样本，可不传。
动作参数volumeUl、durationSec、speedRpm、temperature必须透传决定设备真实执行行为，应在 paramsSchema 和 requestTemplate 中清晰定义。
方法参数methodCode、programNo、channel通常透传设备预置方法、通道、程序号等字段应由流程明确指定。
位置参数slotId、sourceSlotId、targetSlotId按设备透传若设备或集成服务负责搬运动作，需要传；若由 Resource/AGV 模块单独处理，则不要混在仪器指令中。
设备连接host、port、baseUrl、authConfig不透传属于 DeviceInfo，由驱动读取。
解析配置codecId、fieldMapping、validRange不透传属于设备响应解析配置，设备不需要知道。
调度控制resourceEnabled、zoneCode、maxAttempts不直接透传用于 Flow/Resource/Task 调度。只有设备业务需要区域信息时，才另外定义业务字段。
07

回调与输出参数

设备执行完成后，回调进入 DeviceCallbackHandler。输出有两种来源：设备直接给结构化 data，或者给原始 rawResponse 后由 Codec 解析。

回调请求结构

字段是否需要解释
callbackToken必须用于步骤回调校验和 Task 关闭。设备必须带回。
success必须是否执行成功。
data结构化输出设备已经返回标准 Map 时使用，例如 {"ph":7.21}。
rawResponse原始输出设备只返回原始报文时使用。配合 deviceType、commandCode 找到 codec 解析。
deviceType / commandCode解析索引用于查询 DeviceCommand.codecId。缺失时不会走 Codec。
errorCode / errorMsg失败时失败时传给 Flow 状态机和任务回调。

Codec 解析规则

parseType配置字段说明
JSONfieldMapping配置 {"ph":"$.data.ph"}，使用 JSONPath 从原始响应提取字段。
REGEXregexRules配置 {"ph":"PH=([0-9.]+)"}，取第一个捕获组。
HEXhexRules按字节偏移、长度、类型解析十六进制报文。
SCRIPTscriptEngine、scriptContent脚本入参为 raw，返回 Map 或单个结果。
unitConversions后处理对解析后的数值按 value * factor + offset 换算。
validRange后处理超出范围的数值字段会被移除。
步骤成功后，StepSuccessHandler 会先应用 PipelineStep.outputMapping，再把结果写入 ExecutionContext。所以设备输出字段名可以先按设备原始语义解析，再通过 outputMapping 统一成流程语义字段。

配置示例

StepDefinition.defaultParams

默认参数
{
  "durationSec": 60,
  "temperatureCompensation": true,
  "methodCode": "STD_PH",
  "unit": "PH"
}

StepDefinition.paramsSchema

建议 schema 形态
{
  "type": "object",
  "required": ["sampleId", "durationSec"],
  "properties": {
    "sampleId": { "type": "string", "title": "样本编号" },
    "durationSec": { "type": "integer", "title": "测量时长", "unit": "s", "minimum": 1 },
    "temperature": { "type": "number", "title": "补偿温度", "unit": "C" },
    "methodCode": { "type": "string", "enum": ["STD_PH", "FAST_PH"] }
  }
}

PipelineStep.inputMapping

从启动参数和上游输出取值
{
  "sampleId": "${input.sampleId}",
  "temperature": "${s_temp.temperature}",
  "targetPh": "${input.targetPh}",
  "callbackUrl": "${sys.callbackUrl}"
}

DeviceCommand.requestTemplate

HTTP JSON 设备报文模板
{
  "action": "measure",
  "sampleId": "${sampleId}",
  "method": "${methodCode}",
  "durationSec": ${durationSec},
  "temperature": ${temperature},
  "callbackUrl": "${callbackUrl}"
}

设备回调 data

设备已返回结构化结果
{
  "callbackToken": "xxxx",
  "success": true,
  "data": {
    "ph": 7.21,
    "temperature": 25.3
  }
}

设备回调 rawResponse + Codec

设备返回原始响应
{
  "callbackToken": "xxxx",
  "success": true,
  "deviceType": "PH_METER",
  "commandCode": "MEASURE",
  "rawResponse": "{\"data\":{\"phValue\":7.21,\"temp\":25.3}}"
}
DeviceCodec.fieldMapping
{
  "ph": "$.data.phValue",
  "temperature": "$.data.temp"
}
09

当前边界与建议

当前实现边界
  • paramsSchema 当前主要是声明和前端渲染依据，运行时没有统一强校验。
  • PipelineStep.command 暂未在 PipelineGraphBuilder 中覆盖 StepDefinition.command。
  • DeviceCommandSaveReqVO 未暴露 completionMode 字段，虽然 DO 与 SQL 中已存在。
  • httpPath 当前只渲染 executionId 和 callbackToken，不会使用完整运行参数。
  • 非 JSON 请求体不会自动注入系统回调字段。
  • Direct Exec 的 timeoutMs 主要用于查询结果时判定执行超时，不等同于驱动发送超时。
推荐落地规范
  • 参数命名使用英文驼峰或小写驼峰，单位写进字段名，例如 volumeUl、durationSec。
  • 步骤定义只放通用默认值，节点覆盖只放本流程差异值。
  • 样本差异参数优先放 experiment_params，本次执行差异用启动 inputParams。
  • 设备输出先用 Codec 解析成稳定字段，再用 outputMapping 映射成流程语义。
  • 设备模板中显式引用的参数，都应该能在 paramsSchema 或 inputMapping 中找到来源。

接口速查

模块路径说明
设备信息/lab/device-info维护物理设备、协议、连接、认证、心跳、启用状态。
设备指令/lab/device-command维护指令模板、HTTP 路径、Codec、轮询配置。
直接执行POST /lab/device-command/execute不依赖流程，直接触发设备指令，返回 execId。
查询直接执行结果GET /lab/device-command/execute/result按 execId 查询状态、输出、原始响应、错误信息。
响应解析规则/lab/device-codec维护 JSON/REGEX/HEX/SCRIPT 解析规则。
设备回调/device/callback/{executionId}/{nodeId}设备完成后回调，推进流程或 Direct Exec 状态。
