1 现状架构对比

两套系统在技术栈、模块划分、能力覆盖上各有侧重。Librax 强在设备控制与资源调度，Labillion 强在工作流引擎与 AI 智能体。

Librax · 实验室自动化平台 Spring Boot 3.5.5 · Java 17 · MySQL · 自研 DAG 调度器

librax-framework

基础框架层：统一响应封装、全局异常处理、MyBatis-Plus 配置、Jackson 序列化、多租户拦截器、Caffeine 缓存

基础框架多租户

librax-module-flow

自研 DAG 调度引擎，基于 JGraphT 构建 Pipeline 有向无环图。支持步骤编排、条件分支、并行执行、事件驱动状态机。包含 PipelineExecutor、StepExecutor、ExecutionEventLog

DAG 引擎JGraphT状态机

librax-module-device

多协议设备管理框架：TCP Socket、HTTP REST、Serial RS232、Mock 模拟器。DeviceDriver 策略模式、心跳检测、设备状态管理、指令队列。支持 AGV、液体处理站、离心机等设备类型

TCPHTTPSERIALMOCK

librax-module-resource

实验室资源管理：库位 Slot 分配与回收、AGV 运输路径规划、区域 Zone 容量管理、物料 Container 追踪、中转位管理、资源预留与释放

SlotAGVZoneContainer

librax-module-lab

实验样本管理：样本血缘追溯 (Sample Genealogy)、样本分裂/合并/转移操作、样本生命周期追踪、与库位和设备的关联

样本血缘生命周期

librax-module-task

统一任务模型 TaskDO：设备任务、人工任务、AGV 任务的统一抽象。任务状态流转、超时处理、重试机制、任务依赖管理

统一任务超时重试

librax-module-ai (基础)

基础 AI 能力：实验方案推荐、简单的对话接口。尚未集成 SSE 流式输出和 Agent Runtime

AI 基础待增强

librax-module-system

基于 RuoYi 的权限系统：用户/角色/菜单/部门管理、数据权限过滤、操作日志。传统 RBAC 模型，缺少细粒度资源权限

RuoYi RBAC待升级
Labillion-Workflow · 科研工作流系统 Spring Boot 3.5.7 · Java 21 · PostgreSQL · Flowable BPM

labillion-core (Security & RBAC AOP)

安全核心：JWT 认证、AES-256-GCM 加密、RBAC 3D 权限矩阵 (角色×资源×操作)、@RequirePermission 声明式鉴权 AOP、数据隔离拦截器

RBAC 3DAES-256AOP 鉴权

Flowable BPM 工作流

成熟的 BPMN 2.0 工作流引擎：流程设计器、用户任务/服务任务/网关/子流程、act_* 运行时表、流程版本管理、审批流、并行网关

FlowableBPMN 2.0流程设计器

AI Agent Runtime

AI 智能体运行时：AgentExecutor 多步推理、SSE 流式输出注册表、AgentTrace 执行追踪、Spring AI 集成、LLM 模型管理 (多 Provider)、工具调用 Function Calling

AgentSSESpring AIFunction Calling

NotificationCenter 通知中心

统一通知框架：WebSocket STOMP 实时推送、邮件通知、12 种事件类型 (实验完成/审批/告警/AI 结果等)、通知模板、已读/未读状态管理

WebSocketSTOMP邮件12 事件类型

Bio Sample Handlers

生物样本类型处理：SampleTypeHandler 策略模式、SampleTypeRegistry 注册表。支持 Cell（细胞）、Protein（蛋白质）、Plasmid（质粒）、Antigen（抗原）四大类型，各自独立的属性和操作逻辑

CellProteinPlasmidAntigen

Python Executor

Python 计算节点：PythonTaskExecutor 沙箱执行、ExecutionContext 上下文注入、结果回收与类型转换、安全白名单机制、超时控制

Python 沙箱安全白名单

Gantt CPM 调度

甘特图调度器：GanttSchedulePlanner、CPM 关键路径计算、资源冲突检测、DashboardAnomalySupport 异常预警、实验进度可视化

CPM关键路径异常预警

Dashboard & Report

数据看板：实验统计、资源利用率、AI Agent 调用分析、异常趋势、Excel 批量导入/导出、PDF 报告生成

DashboardExcelPDF 报告

4 阶段路线图 · Phase Roadmap

七个阶段，渐进融合。每个阶段独立可交付，降低集成风险。点击展开查看详情。

P1

Phase 1: 基础设施对齐

周期：2-3 周 优先级：P0 依赖：无
待开始 ▼

任务清单

  • Java 17 → Java 21 升级，利用虚拟线程、Pattern Matching、Record Class
  • Spring Boot 3.5.5 → 3.5.7 升级，统一版本
  • 数据库策略决定：双 DB (MySQL + PostgreSQL) 共存 vs 统一迁移
  • 统一 Response 格式：CommonResult<T> 对齐，HTTP 状态码规范
  • 引入 MinIO 依赖，配置对象存储 Bucket 策略
  • 统一 Jackson 序列化配置：日期格式、空值处理、枚举序列化
  • 统一异常码体系：业务异常码分段分配
  • Caffeine + Redis 二级缓存架构对齐

涉及文件/模块

librax-framework/ 统一响应格式和异常处理

CacheConfig.java 二级缓存配置类

P2

待开始 ▼

  • 通知偏好设置 API：用户自定义接收通道和事件类型
  • 灰度发布方案：旧 RBAC 与新 3D 矩阵并行运行期

P3

Phase 3: AI Agent 节点集成

周期：3-4 周 优先级：P1 依赖：Phase 1, Phase 2
待开始 ▼

任务清单

  • 引入 Spring AI 依赖，配置多 Provider (OpenAI/Anthropic/本地模型) 支持
  • 实现 AgentExecutor：多步推理引擎，支持 ReAct/CoT 策略
  • 实现 SSE Registry：管理 SSE 连接生命周期，自动超时回收
  • 实现 AgentTrace：AI 调用链追踪，记录每步推理的 Input/Output/Token 用量
  • LLM Model 管理后台：模型注册、API Key 管理、Token 配额
  • AES-256-GCM 加密器：API Key 加密存储与运行时解密
  • AI Agent 节点类型注册到 DAG 引擎：AgentStepExecutor implements StepExecutor
  • Function Calling 工具注册：设备控制、数据查询、样本操作等可被 Agent 调用
  • Agent 结果写入 ExecutionContext，供下游步骤消费
  • AI Agent 并发控制：令牌桶限流，防止 LLM API 过载

9 技术栈决策 · Tech Stack Decision

针对每个技术选型维度，给出最终决策和理由。

Spring Boot 3.5.5 3.5.7 3.5.7 统一到最新稳定版本，获得 Spring AI、Virtual Thread 等最新特性支持
数据库 MySQL 8.0 PostgreSQL 16 双 DB 共存 (Phase 1) 短期双 DB 共存：Librax 核心业务保留 MySQL，Labillion + Flowable 使用 PostgreSQL。长期评估是否统一到 PostgreSQL。Spring 多数据源 + AbstractRoutingDataSource 路由
认证方式 JWT (RuoYi) JWT + AES-256-GCM JWT + AES-256-GCM 保留 JWT 认证机制，引入 AES-256-GCM 加密用于 API Key 等敏感数据存储。Token 刷新机制统一

消息队列 无 (事件驱动) 无 (Spring Event) Spring Event + 可选 Redis Stream 单体架构下 Spring ApplicationEvent 足够；高吞吐场景引入 Redis Stream 作为轻量 MQ
文件存储 本地文件系统 MinIO MinIO MinIO 兼容 S3 API，支持分布式部署、版本控制、生命周期管理，替代本地文件系统

AI 框架 无 Spring AI Spring AI Spring 官方 AI 抽象层，支持 OpenAI/Anthropic/Ollama 等多 Provider，与 Spring Boot 深度集成
实时通信 无 WebSocket STOMP + SSE WebSocket STOMP + SSE STOMP 用于双向通知推送，SSE 用于 AI Agent 单向流式输出。两种协议各有适用场景，互补使用
ORM 框架 MyBatis-Plus Spring Data JPA MyBatis-Plus 为主 Librax 全量使用 MyBatis-Plus，迁移成本过高。新模块可选用 JPA，但主体保持 MyBatis-Plus
API 文档 Swagger / SpringDoc SpringDoc SpringDoc OpenAPI 3 统一使用 SpringDoc，自动生成 OpenAPI 3.0 规范文档

融合架构核心原则

1. 渐进融合，非破坏性
每个阶段独立可交付，不影响 Librax 现有功能运行。新模块通过接口抽象接入，旧模块保持向后兼容。
2. 接口驱动，松耦合
所有跨模块交互通过接口或事件驱动，避免直接依赖具体实现。Spring Event 作为模块间通信的主要机制。
3. 多租户优先
所有新引入模块必须适配 Librax 的多租户体系，tenant_id 作为数据隔离的基础维度。
4. 可观测性内建
统一审计日志、Agent Trace、设备事件、资源操作全部汇入 UnifiedAuditLog，支持 ELK 检索和分析。
