Code Based Guide

物料与库位模块使用指南

本文基于当前代码实现整理，面向系统使用、联调与二次开发。重点覆盖物料定义、容器类型、物料实例、库位、货架、上架下架、流程物料校验与消耗，并对关键字段给出实际含义、填写建议和当前实现边界。

Material Slot Lab + Resource Updated 2026-07-02
01

模块定位

物料模块属于 lab 域，负责定义“库存里有什么”和“每一个具体容器实例当前装着什么”。库位模块属于 resource 域，负责定义“东西放在哪里”，并把库位作为可调度资源暴露给 AGV、机械臂、设备点位解析等环节。

当前代码中，两者通过 MaterialInstanceServiceImpl 直接调用 SlotInfoService 串联：上架时先占用库位，再把物料实例绑定到该 slotId；下架时先释放库位，再清空物料实例位置。流程执行侧则通过物料校验 SPI 与物料消耗事件，把库存状态接入到 Flow 的节点执行生命周期。

使用主链路
空间建模
维护货架 rack 与库位 slot，建立可寻址的物理位置。
基础定义
维护容器类型与物料定义，形成可复用主数据。
实例入库
创建物料实例，填写批次、余量、状态、效期等库存事实。
上架定位
调用上架接口绑定 instanceId 与 slotId。
流程校验
节点执行前按规则检查可用库存、余量和效期。
消耗追踪
节点成功后异步扣减库存并写入消耗记录。
Core Understanding

这套设计的核心不是单纯做“物料台账”，而是把物料实例、物理库位、流程节点需求打通：物料实例回答“可用多少”，库位回答“在哪里”，校验规则回答“某一步需要什么”。三者共同决定自动化实验是否可以被安全提交和执行。

02

推荐使用流程

1. 先建库位空间
  • 创建 RackInfo：定义货架、工作台、培养箱、冰箱等承载区域。
  • 创建 SlotInfo：定义每个可放置容器的位置，库位编码即 slotId。
  • 固定库位建议填写 zoneCode、rackId、行列层与世界坐标。
  • AGV/设备内部位建议填写 ownerId 与 localIndex。
2. 再建物料基础
  • 创建 ContainerType：定义板、管、瓶、架、孔位等容器形态。
  • 创建 MaterialDef：定义试剂、样本、缓冲液、耗材等内容主数据。
  • 建议让 materialCode 稳定、唯一、可读，避免直接使用供应商临时名称。
3. 入库生成实例
  • 每一瓶、每一管、每一块板创建一条 MaterialInstance。
  • 液体填写 currentVolUl，固体/耗材填写 currentCount。
  • 实例只有 status = AVAILABLE 且未过期，才会被流程物料校验选中。
4. 上架、查询、下架
  • 上架使用 /lab/material-instance/load 绑定实例与库位。
  • 批量上架使用 /lab/material-instance/batch-load，返回失败列表。
  • 下架会清空实例 slotId 与 zoneCode，并释放库位状态。
03

库位模块使用指南

库位模块由 RackInfo 与 SlotInfo 组成。RackInfo 表示一组位置的物理载体或区域，SlotInfo 表示真正参与放置、搬运、定位和资源调度的最小位置单元。

RackInfo 字段解析

字段标签含义与填写建议
id系统主键数据库自增主键，接口更新、删除时使用。业务侧不建议依赖它做跨系统编码。
rackId必填业务编码货架或区域编码，例如 RACK-A、FREEZER-01。被 SlotInfo.rackId 引用。
rackName必填展示名称，建议能让现场人员直接识别位置。
rackType必填承载类型，当前注释给出的值包括 RACK、BENCH、INCUBATOR、FREEZER。
zoneCode必填所属区域编码。流程物料规则会按 zoneCode 限定库存可用范围，所以这里建议与实验区、设备区规划保持一致。
coordX/Y/Z可选货架原点世界坐标，单位毫米。主要服务机械臂、AGV 或后续坐标换算。
rowCount/colCount/layerCount必填货架行、列、层数量。用于描述库位矩阵，不会自动生成 Slot，需要单独维护每个 SlotInfo。
enabled必填是否启用。坐标解析 SPI 会跳过未启用库位；货架启用状态当前更多是管理语义。
remark可选现场备注，例如温控要求、人工限制、维修说明。

SlotInfo 字段解析

字段标签含义与填写建议
id系统主键数据库主键，用于后台更新、删除、详情查询。
slotId必填业务编码库位唯一编码，同时作为资源 ID 纳入调度，例如 RACK-A-01、AGV-01-SLOT-1。物料实例上架时使用的就是它。
slotName可选展示名称，建议与现场标识一致。
slotType必填库位类型：FIXED 固定台面/货架位，AGV 小车载具位，DEVICE 设备内部位置。
slotUsage必填用途约束：ANY、SAMPLE、REAGENT、WASTE、BUFFER、TIP。当前上架代码尚未强制校验用途匹配，建议前端或业务层先按该字段过滤。
zoneCode条件必填固定库位和设备库位建议必填；AGV 临时载具位可以为空。物料上架成功后，实例的 zoneCode 会从库位同步。
rackId可选固定库位所属货架，对应 RackInfo.rackId。AGV 或设备内部位通常不填。
positionRow/Col/Layer可选货架内的行、列、层，1 基编号，方便人工盘点与页面矩阵展示。
coordX/Y/Z可选库位世界坐标，单位毫米。SlotCoordinateSpiImpl 会读取这些坐标供调度/设备定位使用。
ownerId可选AGV 或设备内部位的宿主资源 ID，例如 AGV-01、CENTRIFUGE-01。
localIndex可选宿主资源内的本地位置，例如 SLOT-1、POS-1。
capacity必填注意设计含义是容量上限。当前服务在 status = OCCUPIED 时会拒绝再次占用，所以实际表现接近单容器库位；多容量能力需要进一步调整占用判断。
status运行态EMPTY、OCCUPIED、DISABLED。创建/更新 VO 不直接维护该字段，主要由上架下架逻辑更新，分页查询支持按状态过滤。
currentCount运行态当前占用数量。上架时加一，下架时减一并不小于 0。
occupiedBy运行态当前或最近占用的物料实例 instanceId。多容量场景完整列表应通过 lab_material_instance.slot_id 反查。
enabled必填是否启用。坐标解析会跳过禁用库位；占用逻辑目前主要看 status 是否为 DISABLED。
remark可选库位备注，例如只允许人工操作、禁止放易燃品、临时维修等。
Implementation Note

SlotInfoMapper.occupy 会更新 currentCount、status、occupiedBy；release 会递减数量并在归零时清空 occupiedBy。但 SlotInfoServiceImpl.occupySlot 在发现库位已是 OCCUPIED 时直接拒绝，因此当前版本不要把 capacity > 1 当作已完整可用的多容器库位能力。

04

物料模块使用指南

物料模块分为主数据和运行数据。MaterialDef 是内容定义，例如某种试剂或耗材；ContainerType 是容器形态定义；MaterialInstance 是库存中的每个具体实体；MaterialCheckRule 把流程节点与库存需求关联；MaterialConsumption 记录流程执行产生的库存变更。

ContainerType 字段解析

字段标签含义与填写建议
typeCode必填业务编码容器类型编码，例如 PLATE_96_WELL、TUBE_EP_15ML。被物料实例 typeCode 引用。
typeName必填容器类型名称，用于页面展示。
containerType必填容器大类：PLATE、TUBE、BOTTLE、RACK、VIAL、TIP、CHIP、FILTER、BOX。
hierarchyRole必填层级角色：CARRIER 载具，CONTAINER 容器，WELL 孔位/子单元。
maxVolUl可选最大容量，单位微升。液体容器建议填写，用于后续容量校验和前端提示。
wellCount/Rows/Cols可选孔位数量、行数、列数。板类、架类容器建议填写。
childTypeCode可选子单元类型编码。例如 96 孔板的子类型可以指向孔位类型。
sizeXMm/YMm/ZMm可选容器外形尺寸，单位毫米，用于设备适配和运动规划。
wellSpacingMm可选孔间距，常用于板类容器定位。
material可选容器材质，例如 PP、玻璃等。
specJson可选扩展规格 JSON，适合承载暂未结构化的设备适配参数。
enabled必填是否启用。当前创建物料实例时没有强制校验容器类型启用状态，建议业务侧按启用数据选择。

MaterialDef 字段解析

字段标签含义与填写建议
materialCode必填业务编码物料内容编码，例如 PH-BUFFER-7、ETHANOL-75PCT。建议稳定、唯一、可跨批次复用。
materialName必填物料名称，用于展示和搜索。
contentType必填内容类型：REAGENT、STANDARD、BUFFER、SAMPLE、WASTE、MEDIA、SOLVENT。
unit必填默认单位，例如 ml、ul、mg、g、个。实例库存中液体统一使用 currentVolUl。
supplier/catalogNo/casNo可选供应商、货号、CAS 号，用于采购追溯和合规查询。
concentration可选定义层面的默认浓度。实例可用自己的 concentration 覆盖。
storageTemp可选存储温度要求。当前上架逻辑没有按温度自动匹配库位，建议人工或前端规则辅助。
shelfLifeDays/openLifeDays可选未开封/开封后有效期天数。当前创建实例不会自动计算 expiredAt，需要入库侧或业务逻辑写入。
hazardLevel可选危险等级：NONE、LOW、MEDIUM、HIGH、FLAMMABLE、TOXIC。
specJson可选物料扩展规格 JSON，例如纯度、品牌特殊参数、耗材兼容性。
enabled必填是否启用。当前实例创建未强制检查定义启用状态，使用侧应优先选择启用物料。

MaterialInstance 字段解析

字段标签含义与填写建议
id系统主键数据库主键，用于管理端详情、更新、删除。
instanceId必填业务编码物料实例唯一编号，例如 INST-20260501-0001。上架、下架、消耗记录都使用这个字段追踪实体。
typeCode必填容器类型编码，关联 ContainerType.typeCode。
barcode可选扫码识别码。建议与 instanceId 区分：条码可来自现场标签，实例编号是系统业务身份。
parentId可选父实例编号，用于表达管架里的管、板里的孔等层级关系。
slotIndex可选在父容器内的位置，例如 A1、B3、01。它不是物理库位。
slotId位置态当前物理库位，关联 SlotInfo.slotId。顶层容器才有值，子单元位置跟随父容器。
zoneCode位置态上架后从库位同步而来，用于流程物料校验按区域筛选。不要随意手工改写。
contentType可选当前内容类型。可使用 EMPTY 表示空容器；纯载具也可以为空。
materialCode可选物料内容编码，关联 MaterialDef.materialCode。空容器、载具可以为空。
batchNo / lotNo可选batchNo 建议表示内部批次；lotNo 表示厂家批号。
currentVolUl液体库存当前液体体积，单位微升。流程校验与自动扣减会汇总/扣减该字段。
currentCount计数库存当前数量，用于耗材、固体、计数型库存。若规则同时设置体积和数量，消耗监听优先按体积处理。
concentration可选实例实际浓度，可覆盖物料定义中的默认浓度。
status必填实例状态：AVAILABLE、RESERVED、IN_USE、USED、EXPIRED、DISCARDED。流程只选择 AVAILABLE。
receivedAt/openedAt/expiredAt可选接收、开封、过期时间。物料校验会排除 expiredAt 早于当天的实例。
sourceExecutionId/sourceNodeId可选若物料由流程生产，可记录来源执行与节点，形成产物追溯链。
remark可选实例备注，例如异常标签、人工盘点说明。
05

上架、下架与查询

单个上架

调用 PUT /lab/material-instance/load，请求体包含 instanceId 和 slotId。成功后实例写入库位与区域，库位写入占用状态。

批量上架

调用 POST /lab/material-instance/batch-load。接口逐条尝试，失败项以字符串列表返回，成功项不会因为其他项失败而回滚。

下架

下架会释放库位，并清空实例的 slotId 与 zoneCode。批量下架若存在失败，会抛出“部分下架失败”。

Operational Advice

推荐现场操作顺序是“扫码确认实例 → 选择或扫描库位 → 调用上架 → 再按库位反查确认”。因为上架逻辑同时改两张表，反查 list-by-slots 能最快发现库位状态与实例位置是否一致。

06

流程物料校验与消耗

MaterialCheckRule 用来声明某个流程节点需要的物料。当前规则绑定的是 pipelineStepId，也就是流程步骤节点，而不是抽象步骤模板。Flow 在节点执行前调用物料校验 SPI，节点成功后发布物料消耗事件，由监听器异步扣减库存并写入 MaterialConsumption。

MaterialCheckRule 字段解析

字段标签含义与填写建议
pipelineStepId必填流程节点 ID。规则按这个字段查找，所以复制流程或调整节点后需要确认规则是否仍对应正确节点。
materialCode必填需要的物料编码。虽然底层查询支持按类型筛选，但保存 VO 要求该字段必填。
contentType可选内容类型，可与 materialCode 一起提高匹配精度。
minVolUl液体需求最小所需体积，单位微升。校验时会汇总符合条件实例的 currentVolUl。
minCount计数需求最小所需数量。适合吸头、管、耗材等计数型库存。
zoneCode可选为空时使用请求中的区域；不为空时规则自身限定区域。建议关键物料显式指定，减少跨区误用。
sortOrder必填校验顺序。失败信息会按规则顺序产生，建议按实验步骤中的实际取用顺序配置。

MaterialConsumption 字段解析

字段标签含义与填写建议
executionId/nodeId/attempt流程追踪记录是哪一次流程执行、哪个节点、哪次尝试产生的库存变化。
instanceId/typeCode/materialCode/batchNo物料追踪记录被操作的具体实例及其类型、内容、批次。
action动作动作类型包括 CONSUME、TRANSFER、PRODUCE、DISCARD、RESERVE、RELEASE。当前自动扣减主要写 CONSUME。
volBeforeUl/volChangeUl/volAfterUl体积流水体积变更前、变化量、变更后。消耗时 volChangeUl 为负数。
countBefore/countChange/countAfter数量流水计数变更前、变化量、变更后。适合耗材消耗记录。
fromSlotId/toSlotId可选转移类操作的位置来源和目标。当前自动消耗记录主要使用实例当前 slotId 作为来源。
consumedAt时间消耗发生时间。
流程执行中的库存联动

读取规则

07

当前边界与扩展方向

当前需要注意的边界
  • slotUsage 与物料类型目前没有在上架服务中强制匹配。
  • capacity 字段已存在，但当前占用逻辑等价于单容器库位。
  • shelfLifeDays、openLifeDays 不会自动推导实例过期时间。
  • 物料定义和容器类型的 enabled 状态在实例创建时未强制校验。
  • 批量上架是逐条执行并返回失败列表，成功项不会因后续失败自动回滚。
建议优先扩展的能力
  • 上架前校验 slotUsage、温控、危险等级、库位启用状态。
  • 补齐多容量库位模型，允许 capacity > 1 的真实多实例占用。
  • 入库时根据物料定义自动计算 expiredAt，开封时重算开封后有效期。
  • 为物料校验增加预留/锁定机制，避免并发流程同时消耗同一批库存。
  • 把上架、下架、转移、消耗统一沉淀为库存流水，增强审计与回放能力。
Recommended Convention

如果要把这套模块作为稳定的实验自动化库存底座，建议把“库位是否能放”“物料是否能用”“流程是否能锁定”拆成三个显式判断：上架校验解决空间兼容，流程校验解决库存充足，预留机制解决并发一致性。当前代码已经具备主链路，下一步重点是把这些隐性约定变成服务层强约束。
