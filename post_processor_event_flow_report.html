一、流程拆分总览

绑定4个样本/载具
  -> 查询载具当前位置
  -> AGV搬运到后处理机台
  -> 启动后处理机台任务
  -> 等待机台事件回调
      -> scanFailed：标记扫码失败样本
      -> materialRequired：校验物料
          -> 充足：等待实验结果 -> 保存结果
          -> 不足：查询缺料位置 -> AGV补料 -> 通知机台物料到位 -> 复核物料
              -> 充足：等待补料后实验结果 -> 保存结果
              -> 不足：标记物料不足失败
      -> experimentFinished：直接保存实验结果
AGV 节点前已经增加了“查询载具/物料位置”步骤。AGV 下发报文只接收已经解析好的 sourceArea/sourcePos/desArea/desPos 等字段，不负责自己查询库位。

五、机台事件回调

1. 扫码失败

后处理机台内部扫码失败时，回调等待节点 s_wait_machine_event。

{
  "executionId": "流程执行ID",
  "nodeId": "s_wait_machine_event",
  "success": true,
  "outputs": {
    "eventType": "scanFailed",
    "sampleId": "SAMPLE-001",
    "reason": "barcode_unreadable"
  }
}

2. 请求物料

{
  "executionId": "流程执行ID",
  "nodeId": "s_wait_machine_event",
  "success": true,
  "outputs": {
    "eventType": "materialRequired",
    "materials": [
      {
        "materialCode": "SOLVENT_A",
        "requiredVolume": 1000,
        "unit": "uL"
      }
    ]
  }
}

3. 机台直接完成实验

{
  "executionId": "流程执行ID",
  "nodeId": "s_wait_machine_event",
  "success": true,
  "outputs": {
    "eventType": "experimentFinished",
    "sampleResults": [
      {"sampleId": "SAMPLE-001", "status": "SUCCESS", "result": {}}
    ]
  }
}

4. 物料充足后等待结果

如果走了 materialRequired -> materialEnough=true 分支，最终结果回调节点是：

{
  "executionId": "流程执行ID",
  "nodeId": "s_wait_experiment_result",
  "success": true,
  "outputs": {
    "sampleResults": [
      {"sampleId": "SAMPLE-001", "status": "SUCCESS", "result": {}}
    ],
    "rawResult": {}
  }
}

5. 补料后等待结果

如果走了补料分支，最终结果回调节点是：

{
  "executionId": "流程执行ID",
  "nodeId": "s_wait_experiment_result_after_replenish",
  "success": true,
  "outputs": {
    "sampleResults": [
      {"sampleId": "SAMPLE-001", "status": "SUCCESS", "result": {}}
    ],
    "rawResult": {}
  }
}

七、当前实现注意事项

1. 目前很多 COMPUTE 节点是 mock 定义，真实执行时需要补 Spring Bean 或改造成你已有的服务方法。

2. AGV 下发报文已保持严格结构：{"taskId":"${taskId}","command":"${command}"}，不会额外注入系统字段。

3. 分支节点没有配置 default，这是为了避免当前分支跳过器把重复目标节点误标记为 SKIPPED。所以事件类型必须严格匹配。

4. 当前设备命令是 SYNC，适合本地 mock 跑通。接真实设备时，AGV 和后处理机台大概率要改成 WEBHOOK 或通过独立回调推进。
