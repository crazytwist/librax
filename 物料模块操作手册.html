1模块概览

物料模块负责管理实验室所有物理耗材与试剂的全生命周期，涵盖从入库登记、流程使用到废弃丢弃的完整追踪链路。模块由 4 张核心表构成，各有明确职责：


表名中文名职责
lab_material_def物料定义物料品类目录，描述"什么是这种物料"
lab_material_instance物料实例（库存）每个物理容器/实物的档案，描述"这瓶/这管在哪里、有多少"
lab_material_check_rule物料检查规则流程步骤执行前的物料充足性校验规则，阻止缺料步骤启动
lab_material_consumption消耗记录所有物料操作的审计日志（消耗/转移/产生/废弃）

2物料定义管理

物料定义（lab_material_def）是物料的"品类目录"，描述某种物料的固有属性。一条定义对应多个库存实例，类似于"SKU"与"库存"的关系。

字段说明

字段类型说明是否必填
material_codeVARCHAR物料编码，全局唯一标识（如 PH-BUFFER-7、ETHANOL-75PCT）必填
material_nameVARCHAR物料中文名称（如 pH7 标准缓冲液、75% 乙醇）必填
content_typeVARCHAR物料类型（见下方枚举）必填
unitVARCHAR计量单位：ml、ul、mg、g、个必填
supplierVARCHAR供应商名称可选
catalog_noVARCHAR供应商货号可选
cas_noVARCHAR化学品 CAS 编号，用于危险品追踪可选
concentrationVARCHAR标准浓度描述（如 1mol/L、pH7.0）可选
storage_tempVARCHAR存储温度要求（如 2~8℃、-20℃、室温）可选
shelf_life_daysINT入库后保质期天数，NULL 表示无限期可选
open_life_daysINT开封后有效期天数，NULL 表示开封不限期可选
hazard_levelVARCHAR危险等级（见下方枚举）可选
spec_jsonJSON附加规格参数，如 {"purity":"≥99%","grade":"AR"}可选
enabledBOOLEAN是否启用：1=启用，0=停用必填
remarkVARCHAR备注可选

content_type 枚举

REAGENT 试剂 STANDARD 标准品 BUFFER 缓冲液 SAMPLE 样本 WASTE 废液 MEDIA 培养基 SOLVENT 溶剂

hazard_level 枚举

NONE 无危险 LOW 低危 MEDIUM 中危 HIGH 高危 FLAMMABLE 易燃 TOXIC 毒性

3物料库存管理（实例）

物料实例（lab_material_instance）代表实验室中每一个物理容器或实物，是库存管理的核心实体。每瓶试剂、每支管、每块板都对应一条实例记录。

字段说明

字段类型说明
instance_idVARCHAR实例唯一 ID（如 INST-20260501-0001），系统生成或手动设置
type_codeVARCHAR容器类型（如 PLATE_96_WELL、TUBE_EP_15ML）
barcodeVARCHAR条形码/二维码，扫码操作的唯一标识
parent_idVARCHAR父容器实例 ID（如孔板中的某个孔的父容器是孔板），顶级容器为 NULL
slot_indexVARCHAR在父容器中的位置（如 A1、B3、01），顶级为 NULL
slot_idVARCHAR当前存储货位 ID（仅顶级容器有），引用 lab_slot_info
zone_codeVARCHAR所在区域码，冗余字段用于快速查询（从 slot_id 推导）
content_typeVARCHAR物料类型（与 material_def 一致，EMPTY 表示空容器）
material_codeVARCHAR关联物料定义编码，EMPTY/载体容器为 NULL
batch_noVARCHAR内部批次号，同批到货的物料使用同一批次号
lot_noVARCHAR厂商原始批号（用于外部溯源），区别于内部 batch_no
current_vol_ulDECIMAL当前体积（μL），液体专用，固体为 NULL
current_countINT当前数量，固体/耗材专用，液体为 NULL
concentrationVARCHAR当前浓度（覆盖 material_def 默认浓度，用于稀释后的物料）
statusVARCHAR库存状态（见下方状态机）
received_atDATE入库日期，用于计算保质期
opened_atDATE开封日期，用于计算开封有效期，未开封为 NULL
expired_atDATE过期日期（由 received_at + shelf_life_days 计算）
source_execution_idVARCHAR产生此实例的流程执行 ID（如实验产生的样本）
source_node_idVARCHAR产生此实例的步骤节点 ID，精细追溯来源
remarkVARCHAR备注

状态机（status）

AVAILABLE
可用 — 库存充足，可被检查规则匹配和消耗
RESERVED
已预留 — 某步骤已申报占用，但尚未实际使用
IN_USE
使用中 — 固体/耗材正在被步骤使用
USED
已用完 — 体积/数量降至 0，不再可用
EXPIRED
已过期 — 超出保质期或开封有效期，系统自动标记
DISCARDED
已废弃 — 手动标记丢弃，退出流通

容器层级说明

层级结构（parent_id / slot_index） 物料实例支持层级结构，例如：96 孔板（顶级容器，有 slot_id/zone_code）→ 每个孔（子容器，有 parent_id + slot_index 如 A1）。 顶级容器负责位置信息，子容器通过 parent_id 继承父容器位置。查找区域内可用物料时，系统通过 zone_code 快速定位顶级容器，再向下遍历子容器。

批次追溯说明

字段含义示例
batch_no内部批次号，同一次到货分配同一批次BATCH-20260501-001
lot_no厂商原始批号，用于向供应商追溯ABC12345

内部查询方法（供流程引擎使用）

// 查找指定物料/类型/区域中所有 AVAILABLE 且未过期的实例
selectAvailable(materialCode, contentType, zoneCode) → List<MaterialInstanceDO>

流程执行时，检查规则和消耗逻辑均通过此方法查找合格实例，不会操作已过期或非 AVAILABLE 的物料。

过期判断 实例的 expired_at 字段由入库时的 received_at + shelf_life_days（以及开封后的 opened_at + open_life_days）计算，取较早者。selectAvailable 查询会自动排除 expired_at <= 今日 的实例，防止过期物料进入流程。

4物料检查规则

物料检查规则（lab_material_check_rule）是绑定到流程步骤的前置验证规则。每条规则指定步骤执行前必须备齐的物料类型、数量/体积和区域，不满足则阻止步骤启动，避免实验中途缺料。

字段说明

字段类型说明
pipeline_step_idBIGINT绑定的流程步骤 ID（引用 pd_pipeline_step.id，步骤实例级，非模板）
material_codeVARCHAR要检查的物料编码；与 content_type 至少填一个，可同时使用
content_typeVARCHAR要检查的物料类型（REAGENT/BUFFER 等）；不指定 material_code 时按类型匹配所有该类物料
min_vol_ulDECIMAL最低体积要求（μL），液体专用。区域内所有可用实例体积之和必须 ≥ 此值
min_countINT最低数量要求，固体/耗材专用。区域内所有可用实例数量之和必须 ≥ 此值
zone_codeVARCHAR物料所在首选区域，NULL 表示任意区域均可
sort_orderINT同一步骤有多条规则时的检查顺序
remarkVARCHAR规则说明（如"此步骤约消耗 50μL 缓冲液"）

检查逻辑（MaterialCheckSpiImpl）

步骤即将执行
→
按 sort_order 逐条读取规则
→
查询区域内 AVAILABLE 实例
→
汇总体积/数量
→
满足 → 通过
不满足 → 阻止

液体检查（min_vol_ul）

统计区域内所有匹配实例的 current_vol_ul 之和，若小于 min_vol_ul 则返回失败，错误信息格式：

物料[MATERIAL_CODE]体积不足: 需要 500μL, 可用 120μL (区域=ZONE-A)

固体/耗材检查（min_count）

统计区域内所有匹配实例的 current_count 之和，若小于 min_count 则返回失败：

物料[TUBE_EP_15ML]数量不足: 需要 4 个, 可用 2 个 (区域=ZONE-B)

区域优先级

规则的 zone_code 优先于流程执行上下文中的 zoneCode；若规则 zone_code 为 NULL，则使用上下文 zoneCode；若上下文也无，则搜索全部区域。

5物料消耗记录

消耗记录（lab_material_consumption）是所有物料操作的不可篡改审计日志，由流程引擎在步骤执行后自动写入，也支持手动创建。

字段说明

字段类型说明
execution_idVARCHAR关联流程执行 ID
node_idVARCHAR关联步骤节点 ID
attemptINT重试次数（与 pe_step_execution.attempt 对应）
instance_idVARCHAR操作的物料实例 ID
material_codeVARCHAR物料编码（冗余，供快速查询）
batch_noVARCHAR批次号（冗余，供批次追溯）
actionVARCHAR操作类型（见下方枚举）
vol_before_ulDECIMAL操作前体积（μL），液体专用
vol_change_ulDECIMAL体积变化量：消耗为负，产生为正
vol_after_ulDECIMAL操作后体积 = vol_before_ul + vol_change_ul
count_beforeINT操作前数量，固体专用
count_changeINT数量变化：消耗为负，产生为正
count_afterINT操作后数量 = count_before + count_change
from_slot_idVARCHAR转移操作的来源货位（仅 TRANSFER 使用）
to_slot_idVARCHAR转移操作的目标货位（仅 TRANSFER 使用）
consumed_atDATETIME操作发生时间
remarkVARCHAR备注

action 枚举

CONSUME 消耗 TRANSFER 转移 PRODUCE 产生 DISCARD 废弃 RESERVE 预留 RELEASE 释放预留

自动写入逻辑（MaterialConsumedEventListener）

步骤执行成功后，流程引擎发布 MaterialConsumedEvent，监听器异步处理：

液体（vol_change_ul）

  1. 按顺序遍历区域内 AVAILABLE 实例
  2. 从第一个实例扣减，直至达到规则所需量
  3. 若某实例被扣减至 0，状态改为 USED
  4. 为每次扣减写入消耗记录（含 before/change/after）

固体/耗材（count_change）

  1. 取第一个 AVAILABLE 实例，状态改为 IN_USE
  2. 按规则减少 current_count
  3. 若数量降至 0，状态改为 USED
  4. 写入消耗记录（含 before/change/after）

流程执行中的物料联动

时机系统行为负责组件
步骤执行前 按检查规则逐一验证物料充足性；不足则阻止步骤，返回缺料原因 MaterialCheckSpiImpl
步骤执行成功后 发布 MaterialConsumedEvent，异步扣减物料体积/数量，写入消耗日志 MaterialConsumedEventListener
步骤失败/重试 不扣减物料（事件未发布），attempt 字段记录重试次数 流程引擎
流程取消 已预留的物料自动释放（RESERVED → AVAILABLE） 流程引擎

SPI 集成架构

物料检查通过 SPI（Service Provider Interface）模式与流程引擎解耦：

// librax-module-flow-api（中立接口层）
interface MaterialCheckSpi {
    MaterialCheckResult check(MaterialCheckRequest request);
}

// librax-module-lab（业务实现层）
class MaterialCheckSpiImpl implements MaterialCheckSpi {
    // 查询 lab_material_check_rule + lab_material_instance 执行检查
}

流程引擎调用 SPI 接口，不依赖 lab 模块，避免循环依赖。lab 模块自动注册实现，引擎透明感知。

7完整操作流程

Step 1：创建物料定义

进入 物料定义管理 页面，点击"新增"，填写物料编码、名称、类型、单位、存储条件等固有属性。

一个物料品类只需定义一次，后续每批入库都作为"实例"挂在定义下。

Step 2：物料入库（创建实例）

进入 物料库存管理 页面，点击"新增"，填写：

  • material_code：选择已定义的物料
  • batch_no：此批次的内部批号（同批可使用相同批号）
  • lot_no：厂商批号（从标签抄写）
  • current_vol_ul 或 current_count：初始体积或数量
  • received_at：到货日期（系统据此计算 expired_at）
  • slot_id / zone_code：存放货位

Step 3：配置步骤的检查规则

进入 物料检查规则管理 页面，为指定流程步骤新增规则：

  • 选择 pipeline_step_id（需先在流程中绑定步骤）
  • 指定 material_code 或 content_type（至少填一个）
  • 填写 min_vol_ul（液体）或 min_count（固体）
  • 填写 zone_code（推荐指定区域以提高查询效率）
  • 设置 sort_order（多条规则时的检查顺序）
建议在 remark 中注明"约消耗 XXμL"，方便运营人员了解实际用量与最低储备的差距。

Step 4：流程执行（自动）

流程启动后，物料模块自动介入：

  1. 步骤就绪前，MaterialCheckSpiImpl 逐条验证检查规则 → 通过则允许步骤执行
  2. 步骤成功后，流程引擎发布消耗事件 → MaterialConsumedEventListener 异步扣减库存
  3. 扣减记录自动写入 lab_material_consumption

Step 5：查看消耗记录

进入 物料消耗记录 页面，可按 execution_id、material_code、batch_no、时间范围等筛选，导出 Excel 用于报告。

物料不足的处理方案

场景系统行为处理建议
步骤执行前检查不通过步骤进入等待状态，记录缺料原因补充库存后恢复流程（resume），或手动调整步骤
同批物料体积不足但多批合计够消耗时自动跨实例扣减，优先消耗最早入库的批次无需干预，系统自动处理
物料过期过期实例不参与检查和消耗，等同于不存在入库新批次物料，或人工延期（修改 expired_at 需谨慎）
