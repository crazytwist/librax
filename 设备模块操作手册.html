模块概览

设备模块负责管理实验室中所有物理仪器的接入、指令下发和结果回收。 它是流程引擎（INSTRUMENT 步骤）与真实仪器之间的桥梁。

设备模块由三张核心配置表组成，按照从"设备是什么"→"发什么指令"→"怎么解析响应"的顺序配置：

① 设备信息
lab_device_info
→
② 设备命令
lab_device_command
→
③ 回调解析规则
lab_device_codec
模块表名解决的问题
设备信息 lab_device_info 设备是什么机器、在哪个区域、用什么协议连接
设备命令 lab_device_command 向这台设备发什么指令、请求格式是什么
回调解析规则 lab_device_codec 设备返回的原始报文怎么解析成结构化数据

设备管理

核心概念

一台物理仪器在系统中对应一条 设备信息 记录。 流程引擎通过 设备类型（deviceType） 和 区域（zoneCode） 来查找可用设备， 不绑定具体设备 ID——同一类型同一区域有多台设备时，ResourcePool 会自动调度空闲的那台。

💡 同一区域配置多台相同类型的设备，系统会自动负载均衡，无需手动指定。

字段说明

基础信息

字段必填示例说明
deviceId 必填 PH-METER-01 设备唯一业务 ID，建议格式：类型-序号。全局唯一，创建后不建议修改
deviceName 必填 雷磁pH计1号 设备显示名称，供人识别
deviceType 必填 PH_METER 设备类型码，与流程步骤中的 deviceType 对应。流程引擎按此类型查找设备
zoneCode 必填 ZONE-A 所属实验区域。步骤配置中的 zoneCode 与此匹配才会被调度
protocol 必填 HTTP 通信协议，决定下面哪些连接参数生效。见"通信协议配置"章节
enabled 可选 true 是否启用。禁用后此设备不会被调度，可用于临时下线维护
maxConcurrent 可选 1 最大并发指令数。绝大多数仪器填 1，表示同时只能执行一条指令

状态字段（系统维护，无需手动填写）

字段取值说明
status ONLINE OFFLINE FAULT 设备当前连接状态，由心跳机制自动更新

通信协议配置

根据选择的 protocol，需要填写对应的连接参数。不同协议的字段互不干扰。

HTTP 协议

🌐 适用于设备提供 HTTP/REST 接口的场景，是最常见的接入方式。
字段必填示例说明
baseUrl 必填 http://192.168.1.10:8080 设备 HTTP 服务的根地址，命令的 httpPath 会拼接在后面
callbackMode 必填 WEBHOOK WEBHOOK：设备完成后主动推送结果；POLL：系统定时轮询查询结果
pollIntervalMs POLL模式 2000 轮询间隔（毫秒），仅 POLL 模式生效
authType 可选 TOKEN 认证方式：NONE / BASIC / TOKEN / HMAC
authConfig 按需 {"token":"abc123"} 认证配置 JSON，TOKEN 模式填 {"token":"xxx"}，BASIC 填 {"username":"","password":""}

TCP 协议

字段必填示例说明
host 必填 192.168.1.20 设备 IP 地址或域名
port 必填 4001 TCP 端口号
connectTimeoutMs 可选 5000 建立连接的超时时间（毫秒）
readTimeoutMs 可选 10000 等待读取响应的超时时间（毫秒）

串口（SERIAL）协议

字段示例说明
serialPortCOM3 / /dev/ttyUSB0串口设备路径
baudRate9600波特率，常见值：9600 / 19200 / 115200
dataBits8数据位，通常为 8
stopBits1停止位，通常为 1
parityNONE校验位：NONE / ODD（奇校验） / EVEN（偶校验）

心跳配置（所有协议通用）

⚠️ 心跳用于检测设备是否在线，心跳超时后设备状态自动切换为 OFFLINE。
字段示例说明
heartbeatIntervalMs30000心跳发送间隔（毫秒）。填 0 表示不发送心跳
heartbeatCommandPING心跳使用的指令代码，引用 lab_device_command.command_code

设备命令

命令与指令

命令（Command）定义的是"向这类设备发什么请求"——不绑定具体某台机器，而是绑定 设备类型。 同一设备类型可以有多条命令，如 MEASURE（测量）、CALIBRATE（校准）、PING（心跳）。

流程 YAML 的 INSTRUMENT 步骤通过 deviceType + commandCode 定位到具体的命令配置， 再由 DeviceGateway 选择设备、组装请求报文、发送指令。

字段说明

基础配置

字段必填示例说明
deviceType 必填 PH_METER 关联设备类型，与 lab_device_info.device_type 对应
commandCode 必填 MEASURE 指令代码，同一设备类型内唯一。流程步骤通过此字段引用命令
requestTemplate 必填 {"action":"measure","count":${sampleCount}} 请求报文模板，${参数名} 在执行时被实际参数替换
timeoutMs 可选 30000 此指令的超时时间（毫秒），覆盖设备默认超时
retryable 可选 true 失败后是否可重试。幂等指令（如测量）可以设为 true
codecId 可选 5 关联的回调解析规则 ID（lab_device_codec.id）。不填时原样返回设备响应

HTTP 专用字段

字段示例说明
httpMethodPOSTHTTP 方法：GET / POST / PUT
httpPath/api/measure请求路径，拼接到设备的 baseUrl 后面
contentTypeapplication/json请求 Content-Type

请求模板示例

JSON 格式请求模板
// requestTemplate 字段内容
{
  "action": "measure",
  "sampleCount": ${sampleCount},   // 运行时替换为实际参数
  "channel": ${channel}
}

执行时，流程步骤的 inputParams 中的 sampleCount 和 channel 会自动填入模板。

直接执行（测试用）

在命令配置好之后，可以不通过流程引擎，直接在管理界面向设备发送指令，用于调试和测试设备连通性。

点击"执行"按钮
→
填写执行参数
→
系统分配设备下发指令
→
等待设备回调
→
查看解析结果

执行请求格式

POST /lab/device-command/execute
{
  "deviceType": "PH_METER",      // 必填，设备类型
  "commandCode": "MEASURE",     // 必填，指令代码
  "params": {                     // 可选，替换模板中的 ${} 占位符
    "sampleCount": 1
  },
  "deviceId": "PH-METER-01",    // 可选，指定具体设备；不填则自动分配
  "forceExec": false,           // 是否强制执行（忽略设备忙碌状态）
  "timeoutMs": 30000            // 可选，本次执行超时
}

系统返回

{
  "execId": "de-a1b2c3d4e5f6",   // 执行ID（de- 前缀表示直接执行）
  "deviceId": "PH-METER-01",   // 实际分配的设备
  "status": "EXECUTING"          // 指令已下发，等待回调
}

查询结果

GET /lab/device-command/execute/result?execId=de-a1b2c3d4e5f6
{
  "status": "COMPLETED",
  "outputs": {
    "ph": 7.2,
    "temperature": 25.1
  }
}

轮询模式配置

部分设备在收到指令后，不会立即回调，而是让系统主动来查询结果（POLL 模式）。 此时需要在命令上配置轮询参数。

字段示例说明
pollPath /api/result/${taskId} 轮询查询结果的 HTTP 路径，${taskId} 会被设备返回的任务ID替换
pollDoneExpr $.status == "DONE" 判断设备是否完成的 JSONPath 表达式。表达式为真时停止轮询，开始解析结果
pollMaxTimes 10 最大轮询次数，超过后视为超时失败
⚠️ 轮询间隔由设备信息的 pollIntervalMs 字段控制，不在命令上配置。

回调解析规则（Codec）

什么是 Codec

设备返回的原始报文格式各异——有 JSON、有十六进制字节流、有纯文本。 Codec（编解码规则）的作用就是把设备的"私有格式"翻译成系统统一的结构化 Map， 让流程步骤可以直接用字段名引用数据，如 outputs.ph = 7.2。

设备原始响应
rawResponse
→
选择解析类型
JSON / HEX / REGEX / SCRIPT
→
提取字段值
→
单位换算
→
范围校验
→
结构化 Map
{ph:7.2, temp:25}
💡 Codec 通过 codecId 关联到设备命令。一条 Codec 可被多条命令复用，同类设备共享同一套解析规则。

解析类型总览

JSON 解析
设备返回标准 JSON 格式，用 JSONPath 表达式精确提取字段。
最简单，推荐首选。
HEX 解析
设备返回十六进制字节流（如串口仪器）。按字节偏移量和数据类型逐位解析。
REGEX 正则解析
设备返回纯文本，用正则捕获组提取关键数值。适合老式仪器文本输出。
SCRIPT 脚本解析
用 Groovy 或 JS 脚本处理复杂格式，入参为原始响应字符串，返回 Map。灵活但需要编写代码。

JSON 解析配置

使用 JSONPath 表达式从 JSON 响应中提取字段。fieldMapping 是一个 JSON 对象， key 是输出字段名，value 是 JSONPath 表达式。

fieldMapping 格式
{
  "ph": "$.result.ph",           // 从 result.ph 提取，输出为 ph
  "temperature": "$.result.temp",   // 从 result.temp 提取，输出为 temperature
  "timestamp": "$.ts"            // 从根节点 ts 提取
}
设备原始响应
{
  "result": {
    "ph": 7.23,
    "temp": 25.1
  },
  "ts": 1748000000
}
解析后输出
{
  "ph": 7.23,
  "temperature": 25.1,
  "timestamp": 1748000000
}

HEX 解析配置

hexRules 是一个 JSON 数组，每个元素描述如何从字节流中提取一个字段。

hexRules 格式
[
  {
    "fieldName": "weight",    // 输出字段名
    "byteOffset": 0,          // 从第0字节开始读
    "byteLength": 4,          // 读4个字节
    "dataType": "FLOAT"       // 解释为32位浮点数
  },
  {
    "fieldName": "status",
    "byteOffset": 4,
    "byteLength": 1,
    "dataType": "INT8"
  }
]

支持的数据类型

INT8 INT16 INT32 UINT16 FLOAT（32位） DOUBLE（64位）

正则解析配置

regexRules 是一个 JSON 对象，key 是输出字段名，value 是带捕获组的正则表达式。第一个捕获组的内容作为字段值。

设备原始文本
PH:7.23 TEMP:25.1 STATUS:OK
regexRules 配置
{
  "ph": "PH:([\\d.]+)",
  "temperature": "TEMP:([\\d.]+)"
}

脚本解析配置

当设备响应格式过于特殊，前三种方式无法处理时，使用脚本。 脚本入参为原始响应字符串 raw，返回一个 Map。

Groovy 示例
// scriptEngine: groovy
def parts = raw.split(",")
return [
  "ph": parts[0] as Double,
  "temp": parts[1] as Double
]
JavaScript 示例
// scriptEngine: js
var parts = raw.split(",");
return {
  ph: parseFloat(parts[0]),
  temp: parseFloat(parts[1])
};

后处理：单位换算与范围校验

无论使用哪种解析类型，解析完成后都可以追加两步后处理。

单位换算（unitConversions）

公式：输出值 = 原始值 × factor + offset

示例：摄氏度转华氏度
{
  "temperature": {
    "factor": 1.8,
    "offset": 32.0
  },
  "ph": {                   // 不需要换算，factor=1 offset=0
    "factor": 1.0,
    "offset": 0.0
  }
}

有效范围校验（validRange）

超出范围的字段会从输出 Map 中移除（不是报错，而是静默丢弃）。

示例：pH 值必须在 0~14 之间
{
  "ph": { "min": 0, "max": 14 },
  "temperature": { "min": -50, "max": 150 }
}
⚠️ 范围校验超出后字段被丢弃，后续步骤引用该字段会得到 null。建议在步骤中对关键字段做空值检查。

设备回调机制

回调机制

系统向设备下发指令后进入等待状态。设备完成任务后，通过 HTTP 请求主动回调系统， 将结果推送回来。系统收到回调后，经 Codec 解析，推进流程 DAG 或更新直接执行记录。

系统下发指令
→
设备执行
→
POST 回调接口
→
Codec 解析
→
释放设备 / 推进流程

回调格式

方式一：结构化数据（设备已自行解析）
POST /app-api/device/callback/{execId}/{nodeId}

{
  "callbackToken": "token-abc",  // 必须携带
  "success": true,
  "data": {
    "ph": 7.2,
    "temperature": 25.1
  }
}
方式二：原始报文（系统通过 Codec 解析）
POST /app-api/device/callback/{execId}/{nodeId}

{
  "callbackToken": "token-abc",
  "success": true,
  "rawResponse": "{'result':{'ph':7.2}}",
  "deviceType": "PH_METER",  // 用于查找 Codec
  "commandCode": "MEASURE"
}

失败回调格式

{
  "callbackToken": "token-abc",
  "success": false,
  "errorCode": "DEVICE_ERROR",
  "errorMsg": "传感器读数超量程"
}

回调路由规则

系统通过回调 URL 中的 execId 前缀区分回调来源，自动路由到不同的处理逻辑。

execId 格式来源处理方式
de-xxxxxx 直接执行（测试） 更新 Redis 中的执行记录，可通过 execute/result 接口查询
xxxxxxxx（无前缀） 流程引擎步骤 解析结果后推进流程 DAG，触发下一步骤调度
🔒 安全说明：回调请求必须携带 callbackToken，该 Token 在下发指令时生成，每次执行唯一。Token 不匹配时回调会被拒绝，防止伪造。
